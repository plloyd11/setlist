## Tech Debt

3 items across 2 phases — all low severity, no blockers.

### Phase 9: Setlist Builder Tests
- **SETL-08 fragile locator:** `page.locator('.truncate').innerText()` relies on a single `.truncate` element existing on the setlist detail page. Currently correct but could break if future UI adds another `.truncate` element.

### Phase 10: Band & Multi-User Tests
- **BAND-05 implicit cascade:** Setlist cleanup relies on `ON DELETE CASCADE` from `setlists.band_id` FK rather than explicit `safeDelete`. Correct behavior but undocumented in test code.
- **BAND-01 cleanup pattern:** Uses inline `safeDelete` without `try/finally` — if test fails between creation and cleanup, band record leaks. Low risk since worker teardown cascades bands via `deleteTestUser`.
