  <action>
    1. Create `supabase/migrations/20260218000000_create_songs_table.sql` with the songs table schema from research:
       - `id` uuid primary key with `gen_random_uuid()` default
       - `user_id` uuid references `auth.users(id)` on delete cascade, not null
       - `title` text not null
       - `duration_seconds` integer not null, check > 0
       - `notes` text (nullable)
       - `created_at` timestamptz default now() not null
       - Index on `user_id` for RLS performance
       - Index on `(user_id, title)` for default alphabetical sort
       - Enable RLS with 4 policies (select, insert, update, delete) scoped to authenticated users using `(select auth.uid()) = user_id` pattern (NOT bare `auth.uid()` -- the subselect prevents per-row function calls)

    2. Create `src/lib/types/database.ts` with a `Song` interface:
       ```typescript
       export interface Song {
         id: string;
         user_id: string;
         title: string;
         duration_seconds: number;
         notes: string | null;
         created_at: string;
       }
       ```

    3. Create `src/lib/utils/duration.ts` with two functions:
       - `parseDuration(input: string): number | null` -- parses "mm:ss" to total seconds. Regex: `/^\d{1,3}:[0-5]\d$/`. Returns null for invalid input.
       - `formatDuration(totalSeconds: number): string` -- formats integer seconds to "m:ss" string (e.g., 225 -> "3:45").
  </action>
  <verify>
    - Migration SQL file exists and contains CREATE TABLE, indexes, ALTER TABLE ENABLE RLS, and 4 CREATE POLICY statements
    - `src/lib/types/database.ts` exports Song interface
    - `src/lib/utils/duration.ts` exports parseDuration and formatDuration
    - Run `npx tsc --noEmit` to verify no TypeScript errors
  </verify>
  <done>
    Migration SQL ready to apply. Song type defined. Duration utilities handle mm:ss parsing (including edge cases like "0:00" returning null due to check > 0, "99:59" as valid) and formatting.
  </done>

       - Default form action that:
         a. Gets session via `locals.safeGetSession()`

         f. On Supabase error, return `fail(500, { ..., error: 'Failed to save song' })`
         g. On success, return `{ success: true }`
       - Return form field values in fail() responses so the form preserves user input on error
