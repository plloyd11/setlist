**+page.server.ts** — Create server load and actions:

Load function:
- Validate setlist belongs to user (query setlists where id=params.id AND user_id=session.user.id)
- If not found, throw error(404)
- Load setlist_songs with joined song data: `supabase.from('setlist_songs').select('id, position, song_id, songs(id, title, duration_seconds)').eq('setlist_id', params.id).order('position')`
- Load user's full song library: `supabase.from('songs').select('*').eq('user_id', session.user.id).order('title')`
- Load user's profile (for logo_url in header): `supabase.from('profiles').select('*').eq('id', session.user.id).maybeSingle()`
- Return `{ setlist, setlistSongs, songs, profile }`

Actions:
- `updateSetlist`: Accept form data for gig_date, venue, target_seconds, transition_seconds. Update the setlist row. Return success.
- `saveOrder`: Accept JSON body with `items: Array<{ song_id: string, position: number }>`. Delete all existing setlist_songs for this setlist_id, then insert new rows with sequential positions. This is the "delete-all-reinsert" pattern from research to avoid unique constraint issues.
- `addSong`: Accept song_id. Query max position, insert at max+1. Return the new setlist_song row.
- `removeSong`: Accept setlist_song_id. Delete from setlist_songs. Re-normalize positions (delete-all-reinsert remaining songs in order).

**Drag-and-drop setup using svelte-dnd-action:**

State management:
- `let libraryItems = $state(data.songs.map(s => ({ ...s, id: s.id })))` — library songs
- `let setlistItems = $state(data.setlistSongs.map(ss => ({ id: ss.id, song_id: ss.song_id, title: ss.songs.title, duration_seconds: ss.songs.duration_seconds, position: ss.position })))` — flattened setlist songs where `id` is the setlist_songs.id (NOT the song.id, to avoid duplicates)

Library zone (source):
- `use:dndzone={{ items: libraryItems, flipDurationMs: 200, type: 'setlist-songs', dropFromOthersDisabled: true }}`
- `onconsider`: update libraryItems from e.detail.items
- `onfinalize`: RESET libraryItems back to data.songs (copy-on-drag pattern — songs stay in library after drag)

Setlist zone (target + reorder):
- `use:dndzone={{ items: setlistItems, flipDurationMs: 200, type: 'setlist-songs' }}`
- `onconsider`: update setlistItems from e.detail.items
- `onfinalize`: update setlistItems, then persist to DB. When a new item arrives from library (it will have a song id as its `id`), detect it's new (not an existing setlist_song), generate a new UUID for it using `crypto.randomUUID()`, and add it. Then call saveOrder action with the full ordered list.
- IMPORTANT: Items dragged from library will have their song.id as the item id. After finalize in setlist zone, check if any item's id matches a song.id (not a setlist_song.id). If so, this is a newly added song — assign it a new setlist_songs.id. This avoids the duplicate ID pitfall from research.

Persist after finalize:
- After setlist zone finalize, POST to saveOrder action with the full list of { song_id, position } pairs (position = array index)
- Use `fetch` with form data or a client-side Supabase call. Simplest: use Supabase client directly — delete all setlist_songs for this setlist_id, then insert new rows. Call `invalidateAll()` after to sync server data.
- Use optimistic updates: the UI updates immediately from $state, the DB sync happens in background.

- Props: `percent` (number 0-150), `isOver` (boolean)
- Visual: horizontal bar that fills from left to right

- The bar width = `min(percent, 100)%`. When over 100%, the bar is full and red.
- Height: h-3 rounded-full
- Smooth width transition: `transition-all duration-300`
- Accessible: role="progressbar", aria-valuenow, aria-valuemin=0, aria-valuemax=100

**TimingBar.svelte** — Create `src/lib/components/setlists/TimingBar.svelte`:
- Props: `setlistItems` (array of songs with duration_seconds), `targetSeconds` (number | null), `transitionSeconds` (number), `onTargetChange` (callback), `onTransitionChange` (callback)
- Sticky positioning: `sticky bottom-0` (or top — bottom is better so it's always visible while scrolling the setlist)
- Background: bg-white dark:bg-stone-900, border-t, shadow-up, py-3 px-4

Computed values (all using `$derived`):
- `totalSongSeconds`: sum of all setlistItems[].duration_seconds
- `totalTransitionSeconds`: (setlistItems.length > 1) ? (setlistItems.length - 1) * transitionSeconds : 0
- `totalSeconds`: totalSongSeconds + totalTransitionSeconds
- `overUnderSeconds`: targetSeconds ? totalSeconds - targetSeconds : 0
- `progressPercent`: targetSeconds ? Math.min((totalSeconds / targetSeconds) * 100, 150) : 0
- `isOver`: targetSeconds ? totalSeconds > targetSeconds : false

Layout (flex row, items-center, gap-4):
1. **Total time display**: Large text showing formatted total time (e.g., "45:30"). Use formatDuration from `$lib/utils/duration`. Label "Total" above in small text.
2. **Target time input**: Small input field for target time in mm:ss format. On blur/change, parse with parseDuration and call onTargetChange. Label "Target" above. If no target set, show placeholder "Set target".
3. **Over/under indicator**: Show the difference as "+5:30" (red text) or "-3:00" (green text) when target is set. Use `text-red-500` for over, `text-emerald-500` for under. Only visible when target is set.
4. **Progress bar**: ProgressBar component spanning available width. Only visible when target is set.
5. **Transition stepper**: A number input or +/- stepper for transition time in seconds. Label "Gap" above. Min 0, max 300 (5 min). On change, call onTransitionChange. Display as "30s" or "1:00" format.

The timing bar must be ALWAYS VISIBLE (sticky) per user decision. It should work on both mobile and desktop — on mobile it might stack vertically or use a more compact layout.
