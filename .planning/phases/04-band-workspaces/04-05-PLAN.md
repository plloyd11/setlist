**1. src/routes/(app)/bands/[id]/setlists/[setlistId]/+page.server.ts:**

Mirror the personal setlist builder's server logic (`src/routes/(app)/setlists/[id]/+page.server.ts`) with one critical difference: load band songs instead of personal songs.

**Load function:**
- Get session. If no session, error 401.
- Load setlist: `supabase.from('setlists').select('*').eq('id', params.setlistId).eq('band_id', params.id).single()`. Verify it belongs to this band.
- Load setlist songs (current order): `supabase.from('setlist_songs').select('id, song_id, position, songs(id, title, duration_seconds, notes)').eq('setlist_id', params.setlistId).order('position')`.
- Load band songs (library panel): `supabase.from('band_songs').select('song_id, songs(id, title, duration_seconds, notes)').eq('band_id', params.id).order('songs(title)')`. This is the KEY DIFFERENCE from personal builder.
- Return `{ setlist, setlistSongs, librarySongs }`.

**Form actions:**
Copy ALL form actions from the personal builder (saveOrder, addSong, removeSong, updateSetlist, toggleShare). These operate on the setlists and setlist_songs tables which are band-accessible via RLS. The actions are identical -- they don't need to know about band context because RLS handles authorization.
