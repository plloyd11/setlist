  <name>Task 1: Create band database migration with tables, RLS, and helper function</name>
  <files>supabase/migrations/20260221000000_create_band_tables.sql</files>
  <action>
Create a new migration file with ALL of the following, in this order:

1. **user_band_ids() security definer function** -- returns UUID array of band IDs for current user. Mark as `security definer stable`. This MUST be created before RLS policies that reference it.

2. **bands table** -- id (uuid PK, gen_random_uuid default), name (text not null), owner_id (uuid FK to auth.users on delete restrict, not null), logo_url (text nullable), created_at (timestamptz default now), updated_at (timestamptz default now). Enable RLS. Policies:
   - Authenticated SELECT: `id = any((select public.user_band_ids()))`
   - Authenticated INSERT: `(select auth.uid()) = owner_id`
   - Authenticated UPDATE: `(select auth.uid()) = owner_id` (both using and with check)
   - Authenticated DELETE: `(select auth.uid()) = owner_id`
   - Anon SELECT: `id in (select band_id from public.setlists where share_token is not null and band_id is not null)` -- for shared band setlist public views

3. **band_members table** -- id (uuid PK), band_id (uuid FK to bands on delete cascade, not null), user_id (uuid FK to auth.users on delete cascade, not null), role (text not null default 'member', check in ('owner', 'member')), joined_at (timestamptz default now). UNIQUE(band_id, user_id). Enable RLS. Policies:
   - Authenticated SELECT: `band_id = any((select public.user_band_ids()))`
   - Authenticated INSERT: owner-only via subquery on bands.owner_id
   - Authenticated DELETE: owner-only via subquery on bands.owner_id

4. **band_songs table** -- id (uuid PK), band_id (uuid FK to bands on delete cascade, not null), song_id (uuid FK to songs on delete cascade, not null), added_by (uuid FK to auth.users on delete set null), added_at (timestamptz default now). UNIQUE(band_id, song_id). Enable RLS. Policies:
   - Authenticated SELECT/INSERT/DELETE: `band_id = any((select public.user_band_ids()))`

5. **band_invites table** -- id (uuid PK), band_id (uuid FK to bands on delete cascade, not null), token (uuid unique default gen_random_uuid, not null), created_by (uuid FK to auth.users on delete set null), used_by (uuid FK to auth.users on delete set null), used_at (timestamptz nullable), created_at (timestamptz default now), expires_at (timestamptz default now + 7 days). Enable RLS. Policies:
   - Authenticated INSERT: owner-only via subquery
   - Authenticated SELECT: `used_at is null and expires_at > now()` (valid invites visible to all authenticated)
   - Authenticated UPDATE: `used_at is null and expires_at > now()` using, `used_by = (select auth.uid())` with check

6. **ALTER setlists** -- Add nullable band_id FK to bands on delete cascade. Add partial index on band_id where not null. Add new RLS policies for band member access:
   - Authenticated SELECT: `band_id = any((select public.user_band_ids()))`
   - Authenticated INSERT: `band_id = any((select public.user_band_ids()))` with check
   - Authenticated UPDATE: `band_id = any((select public.user_band_ids()))`
   - Authenticated DELETE: `band_id = any((select public.user_band_ids()))`

7. **Additional setlist_songs RLS** -- Band members can manage songs in band setlists:
   - Authenticated ALL: `setlist_id in (select id from public.setlists where band_id = any((select public.user_band_ids())))`

8. **Additional songs table RLS** -- Band members can view and update songs linked to their bands:
   - Authenticated SELECT: `id in (select song_id from public.band_songs where band_id = any((select public.user_band_ids())))`
   - Authenticated UPDATE: `id in (select song_id from public.band_songs where band_id = any((select public.user_band_ids())))`

9. **Indexes** (critical for RLS performance):
   - band_members(user_id)
   - band_members(band_id)
   - band_songs(band_id)
   - band_songs(song_id)
   - band_invites(token) WHERE used_at IS NULL
   - setlists(band_id) WHERE band_id IS NOT NULL

10. **Storage policy for band logos** -- Band owner can upload to `bands/{band_id}/` folder in logos bucket:
    - INSERT: `bucket_id = 'logos' and (storage.foldername(name))[1] = 'bands'` and band ownership check
    - UPDATE/DELETE: same pattern

11. **Additional profiles table RLS** -- Authenticated users must be able to read profiles of their bandmates. The existing "Anyone can view profiles" policy only applies to the `anon` role (unauthenticated). Add:
    ```sql
    CREATE POLICY "Band members can view profiles of their bandmates"
      ON public.profiles FOR SELECT TO authenticated
      USING (id IN (
        SELECT user_id FROM public.band_members
        WHERE band_id = ANY((SELECT public.user_band_ids()))
      ));
    ```
    This is CRITICAL -- without it, authenticated Supabase queries joining profiles from band_members will return null for all bandmates (the existing "Users can manage their own profile" policy restricts authenticated reads to the user's own row only).

Follow the exact SQL patterns from the research document. Use `(select auth.uid())` wrapped in SELECT for RLS performance (matching existing migration conventions).
