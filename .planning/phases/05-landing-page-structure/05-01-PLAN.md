<objective>
Set up auth-based routing so logged-out visitors can reach `/` (for the landing page in Plan 02) while logged-in users are redirected to the dashboard at `/dashboard`.

Purpose: The landing page must be accessible without authentication, but the current auth guard blocks all non-/auth, non-/share routes. The dashboard currently lives at `/` inside the (app) route group, which would conflict with a root-level landing page. This plan resolves both issues.

Output: Working routing infrastructure where `/` is unprotected, logged-in users redirect to `/dashboard`, and the dashboard lives at its new URL with all nav links updated.
</objective>

    ```
    if (
      !event.url.pathname.startsWith('/auth') &&
      !event.url.pathname.startsWith('/share') &&
      event.url.pathname !== '/'
    ) {
    ```
    This allows logged-out visitors to reach `/` without being redirected to /auth.

    2. Create `src/routes/+page.server.ts` (root level, NOT inside (app)):
    ```typescript
    import { redirect } from '@sveltejs/kit';
    import type { PageServerLoad } from './$types';

    export const load: PageServerLoad = async ({ locals: { safeGetSession } }) => {
      const { session } = await safeGetSession();
      if (session) {
        throw redirect(303, '/dashboard');
      }
      return {};
    };
    ```
    This ensures logged-in users never see the landing page — they go straight to the dashboard via server-side redirect (no flash of wrong content).

    3. Update `src/routes/auth/callback/+server.ts`: Change the default redirect from `'/'` to `'/dashboard'`. The line `const redirectTo = url.searchParams.get('redirect') || '/';` becomes `const redirectTo = url.searchParams.get('redirect') || '/dashboard';`. This prevents a redirect loop where a user signs up, gets sent to `/`, and the server load redirects them again.
